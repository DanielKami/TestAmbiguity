🏗️ Build and Deployment Notes
This section outlines the requirements and steps needed to build the Super Fast Ambiguity Library (v3.0) and deploy it for use in host applications (like C# or C++).

📦 Required Dependencies
To successfully run any host application that calls the functions in this library, the following files must be present in the same directory as the host executable (.exe):

Ambiguity.dll:

This is the primary library file generated by compiling this project.

It contains all the exported functions (Initialize, Run, Release, etc.) and the optimized CUDA kernels.

NVIDIA CUDA Runtime DLLs:

As this library relies on the NVIDIA CUDA Toolkit, the corresponding runtime components must be accessible by the operating system.

Specifically, you will need the DLLs for the CUDA Runtime and the cuFFT library that are linked into Ambiguity.dll.

The required files are typically located in the CUDA Toolkit installation path (e.g., C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.x\bin).

The most common required DLLs are:

cudart64_[version].dll

cufft64_[version].dll

The simplest approach is ensuring the CUDA bin directory is correctly added to the system's PATH environment variable during the CUDA Toolkit installation.

⚙️ Compilation Notes (Visual Studio 2022)
The library is a native C++ project requiring specific configuration to integrate the CUDA toolchain.

1. Project Configuration
Platform: Ensure you are targeting the correct platform (x64). CUDA acceleration requires a 64-bit build.

CUDA Integration: The Visual Studio Extension for CUDA must be installed (it comes with the CUDA Toolkit installer).

Verify that Ambiguity.cu has its Item Type set to CUDA C/C++ in the file properties.

Compiler Flags: The native code utilizes advanced features:

OpenMP: Used for CPU-side post-processing (#define PARALLEL).

Precomputed Tables: Enabled by the #define PRECOMPUTE macro in Ambiguity.h for GPU kernel optimization.

2. Output File
The final output will be the dynamic link library:

$$\text{Project_Directory}\backslash\text{x64}\backslash\text{Release}\backslash\textbf{Ambiguity.dll}$$
3. Error Handling
The native code returns descriptive negative integer values on failure. All host applications (like C#) should check the return value of Initialize and Run to ensure successful execution. Error codes are defined in Ambiguity.h (e.g., CUDA_MALLOC_ERROR).

🔗 Using the Library in C#
When using the C# test application (PerformanceTester), remember that the P/Invoke declarations rely on a specific calling convention:

Calling Convention: All exported functions use CallingConvention.Cdecl.

Data Types: Use IntPtr for Pinned Memory access, and float[] for standard Heap Memory array marshaling.

Deployment Requirement: The Ambiguity.dll must be in the execution path of the C# application.
